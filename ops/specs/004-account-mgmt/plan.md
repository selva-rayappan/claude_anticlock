# Implementation Plan: Account Management

**Branch**: `004-account-mgmt` | **Date**: 2026-06-15 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/004-account-mgmt/spec.md`

## Summary

Implement user self-service account management for OpsNext: profile editing (display name,
job title, avatar), in-session password change, per-category notification preferences
(in-app and email channels), personal API token generation and revocation, and account
self-deletion with PII anonymisation. All operations are scoped to the signed-in user's
own record within their tenant; no cross-user editing is exposed through this feature.

## Technical Context

**Language/Version**: Java 21 (backend) · TypeScript / Node 20 (frontend)

**Primary Dependencies**: Spring Boot 3.4.1 · Spring Security · JJWT 0.12.6 (backend);
Next.js 15 App Router · React 19 · shadcn/ui · TanStack Query · react-hook-form · Zod
(frontend); MinIO (avatar object storage, pre-signed PUT URLs); `java.security.SecureRandom`
for opaque token generation (backend)

**Storage**: PostgreSQL 16 (schema-per-tenant via TenantJdbcTemplate) · Redis 7 (personal
API token deny-list for immediate revocation; session invalidation on account deletion)

**Testing**: JUnit 5 + Spring Boot Test (backend) · Vitest + Testing Library (frontend)

**Target Platform**: Linux container (backend API) · Browser / Next.js SSR (frontend)

**Project Type**: Multi-tenant SaaS web application (monorepo: `apps/api` + `apps/web`)

**Performance Goals**: Profile update ≤ 500 ms p95; password change ≤ 300 ms p95;
notification preference save ≤ 200 ms p95; token generation ≤ 200 ms p95

**Constraints**: Avatar raw bytes never stored in PostgreSQL — only the CDN URL; token raw
value shown exactly once, only the SHA-256 hash persisted; account deletion must invalidate
all active JWT sessions via Redis deny-list; last-Admin guard enforced at service layer;
email address field read-only (change flow deferred to future phase)

**Scale/Scope**: Per-user settings; no fan-out writes on save; notification preference
lookup per-event must remain ≤ 30 ms p95 (Redis cache acceptable)

## Database Migrations

All tables in `tenant_{slug}` schema via Flyway tenant migration scripts:

```sql
-- V004.1__user_profile.sql
CREATE TABLE user_profile (
    user_id    UUID PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
    first_name VARCHAR(100) NOT NULL,
    last_name  VARCHAR(100) NOT NULL,
    job_title  VARCHAR(150),
    avatar_url TEXT,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- V004.2__notification_preference.sql
CREATE TYPE notification_category AS ENUM (
    'TASK_REMINDER','DEAL_STAGE_CHANGE','CONTACT_ASSIGNMENT','MENTION','WEEKLY_SUMMARY'
);
CREATE TABLE notification_preference (
    user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    category        notification_category NOT NULL,
    in_app_enabled  BOOLEAN NOT NULL DEFAULT TRUE,
    email_enabled   BOOLEAN NOT NULL DEFAULT TRUE,
    PRIMARY KEY (user_id, category)
);

-- V004.3__personal_api_token.sql
CREATE TABLE personal_api_token (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id      UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    tenant_id    UUID NOT NULL,
    name         VARCHAR(100) NOT NULL,
    token_hash   VARCHAR(64) NOT NULL UNIQUE,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    last_used_at TIMESTAMPTZ,
    revoked_at   TIMESTAMPTZ
);
CREATE INDEX idx_pat_user_active ON personal_api_token(user_id) WHERE revoked_at IS NULL;
```

## API Contracts

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/api/v1/account/profile` | Session | Fetch own profile |
| PUT | `/api/v1/account/profile` | Session | Update name / job title |
| POST | `/api/v1/account/avatar` | Session | Get pre-signed PUT URL for avatar upload |
| DELETE | `/api/v1/account/avatar` | Session | Remove avatar; restore initials fallback |
| POST | `/api/v1/account/password` | Session | Change password (current + new) |
| GET | `/api/v1/account/notification-preferences` | Session | Fetch all preference rows |
| PUT | `/api/v1/account/notification-preferences` | Session | Bulk-upsert preferences |
| GET | `/api/v1/account/tokens` | Session | List active personal API tokens |
| POST | `/api/v1/account/tokens` | Session | Create token (returns raw value once) |
| DELETE | `/api/v1/account/tokens/{id}` | Session | Revoke token immediately |
| DELETE | `/api/v1/account` | Session | Delete own account (body: `{ password }`) |

All responses use `{ data, meta, errors }` envelope per Constitution Principle II.
