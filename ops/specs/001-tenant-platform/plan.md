# Implementation Plan: Tenant & Platform Management

**Branch**: `002-tenant-platform` | **Date**: 2026-06-15 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-tenant-platform/spec.md`

## Summary

Implement the Platform Admin layer of OpsNext: tenant provisioning (PostgreSQL schema
creation + role seeding + invitation email), tenant suspension/deactivation with instant
session invalidation, a monitoring dashboard showing per-tenant usage metrics, subscription
tier assignment with enforcement, and async GDPR data export. Backend exposes
`/api/v1/platform/` endpoints accessible only to `PLATFORM_ADMIN` role; frontend adds
a Platform Admin section at `/platform/`.

## Technical Context

**Language/Version**: Java 21 (backend) · TypeScript / Node 20 (frontend)

**Primary Dependencies**: Spring Boot 3.4.1 · Spring Security · Flyway (DB migrations) ·
Spring Mail / SendGrid (email) · Spring `@Async` + Redis Streams (export job queue) ·
Next.js 15 App Router · React 19 · shadcn/ui · TanStack Query · Recharts (metrics charts)

**Storage**: PostgreSQL 16 (`public` schema for platform entities; `tenant_{slug}` schemas
per tenant) · Redis 7 (session invalidation publish, metrics cache, export job state)

**Testing**: JUnit 5 + Spring Boot Test · Vitest + Testing Library

**Target Platform**: Linux container (backend) · Browser / Next.js SSR (frontend)

**Project Type**: Multi-tenant SaaS web application — `apps/api` + `apps/web` Turborepo

**Performance Goals**: Provisioning completes in ≤ 30 s end-to-end; monitoring dashboard
loads ≤ 3 s for 500 tenants; session invalidation on suspension within 5 s

**Constraints**: Platform Admin routes require `PLATFORM_ADMIN` role — completely separate
from tenant-level `ADMIN` role; all platform operations logged with actor + timestamp

**Scale/Scope**: Supports provisioning of ≥ 500 tenants; export handles ≥ 10,000 records
