# Implementation Plan: Authentication & Authorisation

**Branch**: `003-auth-authz` | **Date**: 2026-06-15 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/003-auth-authz/spec.md`

## Summary

Implement the full authentication and authorisation layer for OpsNext: secure email/password
sign-in with session management, self-service password reset, role-based access control
(Admin / Sales Manager / Sales Rep / Read-Only), account lockout after brute-force attempts,
and optional per-user TOTP multi-factor authentication. The backend exposes REST endpoints
under `/api/v1/auth/` and `/api/v1/users/`; the frontend covers sign-in, forgot-password,
reset-password, user management, and security-settings pages.

## Technical Context

**Language/Version**: Java 21 (backend) · TypeScript / Node 20 (frontend)

**Primary Dependencies**: Spring Boot 3.4.1 · Spring Security · JJWT 0.12.6 (backend);
Next.js 15 App Router · React 19 · shadcn/ui · TanStack Query · react-hook-form · Zod (frontend);
`otplib` or `@otpauth/totp` for TOTP (frontend QR display) · TOTP via standard Java TOTP library (backend)

**Storage**: PostgreSQL 16 (schema-per-tenant via TenantJdbcTemplate) · Redis 7 (session
deny-list, lockout counters, password-reset token cache)

**Testing**: JUnit 5 + Spring Boot Test (backend) · Vitest + Testing Library (frontend)

**Target Platform**: Linux container (backend API) · Browser / Next.js SSR (frontend)

**Project Type**: Multi-tenant SaaS web application (monorepo: `apps/api` + `apps/web`)

**Performance Goals**: Sign-in response ≤ 300 ms p95; session validation ≤ 50 ms p95
(Redis-backed deny-list check)

**Constraints**: httpOnly cookie for refresh token — no token in localStorage; OWASP Top 10
compliance; no stack traces in API error bodies; virtual threads on all request paths

**Scale/Scope**: Supports ≥ 500 concurrent tenants, ≥ 10,000 concurrent authenticated users
